## First Workflow

Daily Command Loop:

1. Ingest: read the latest progress ledger, repo status, and active launch blockers.
2. Select: choose one highest-leverage objective for the day.
3. Route: classify the objective into business, creator, learning, growth, health, wealth, family, swarm, or quality lane.
4. Queue: create one bounded worker task only when parallel execution is useful.
5. Execute: edit or run checks inside the owning repo; keep scope tight.
6. Verify: run the repo health gate, proof check, screenshot, eval, or progress collector.
7. Record: update the ledger and attach evidence paths.

Stop condition:
- A verified artifact exists, or the work is blocked by a named human approval, login, secret, billing, DNS, production, or destructive gate.

## Swarm Objective

Objective: operate bounded swarms and loops that improve business ops, learning, growth, success, and excellence without losing context or crossing safety gates.

Coordinator:
- `SO` owns cross-repo strategy, governance, queue design, evals, and synthesis.

Worker lanes:

| Lane | Expected artifact | Allowed action | Stop condition |
|---|---|---|---|
| Estate mapper | Repo/module evidence map | Read registries and repo docs | Map has evidence labels |
| Module builder | Profile/schema/docs/code patch | Edit ALOS-owned files | Tests and generation pass |
| Growth/release | Download or offer checklist | Draft public-safe copy and blockers | Public-safety gate listed |
| Evals/safety | Gate checklist and residual risks | Run tests, health checks, progress collector | Evidence path recorded |
| Vertical specialist | Domain packet | Work inside one vertical repo | No private-data leakage |

Every worker must receive input context, expected artifact, allowed tools, stop condition, and handoff format. One coordinator owns synthesis and risk decisions.
